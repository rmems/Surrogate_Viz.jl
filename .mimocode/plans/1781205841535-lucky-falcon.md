# Code Review: Surrogate_Viz.jl

## Critical Issues

### 1. Dead CUDA Extension (`ext/CUDABackendExt.jl`)
**Severity: CRITICAL** — The entire 160-line extension file is never loaded. `Project.toml` has no `[extensions]` section, so Julia never loads `ext/CUDABackendExt.jl`. Meanwhile `src/cuda_backend.jl` contains duplicate method definitions that do load. The extension has a better GPU histogram kernel (`hist_kernel!` with `@atomic`) that is completely unused.

**Fix:** Either add `[extensions]` to `Project.toml` and delete `src/cuda_backend.jl`, OR delete `ext/CUDABackendExt.jl` and keep `src/cuda_backend.jl`.

### 2. XSS Vulnerability in Dashboard (`scripts/build_saaq_dashboard.jl:214-223`)
**Severity: CRITICAL** — User data (`run_id`, `model_family`, `saaq_formula_version`, `telemetry_source`) is interpolated into HTML without `html_escape()`. The warnings table correctly escapes but the main run table does not.

**Fix:** Wrap all interpolated values in `html_escape(...)`.

## High Severity

### 3. Dead Code in `src/Surrogate_Viz.jl`
- **Line 326:** `function compute_delta_per_tick end` — bare stub overwritten by `include("kernels.jl")`
- **Lines 328-330:** `_nothing_to_missing` — never called anywhere

### 4. Dead `compute_heatmap_data` Stub (`scripts/build_saaq_dashboard.jl:23-37`)
Returns empty Dict always. `build_heatmap_panel` (lines 39-60) is dead code as a result. The heatmap HTML section is still emitted at line 232 but will always be empty.

### 5. Fragile `has_cuda()` Implementation (`src/backend.jl`)
- Uses internal `Base.require` API (line 9) — not stable across Julia versions
- Catch list too narrow (line 17) — misses `UndefVarError`, `MethodError`
- Re-evaluates on every call — should be cached in a `const Ref`

### 6. `methods()` Check in `kernels.jl:91`
`methods(cuda_best_walker_density_histogram)` at runtime is fragile and O(n). If another method is added, the `isempty` check breaks.

## Medium Severity

### 7. `model_descriptor` Populated from `checkpoint_path` (`src/Surrogate_Viz.jl:260`)
Semantic mismatch — struct field `model_descriptor` is filled from JSON key `"checkpoint_path"`. Likely copy-paste issue.

### 8. `rounded == 0.0 && (rounded = 0.0)` (`src/Surrogate_Viz.jl:148`)
Works for `-0.0` normalization but reads as a no-op. Should be `rounded == -0.0 && (rounded = 0.0)` or use `signbit`.

### 9. `validate_grok_ozempic_bundle` is Shallow (`src/grok_ozempic.jl:100-118`)
Only checks file existence, valid JSON, and `"status"` key. Does not validate numeric types, array structures, or any of the ~15 fields.

### 10. Repetitive Metric Emission (`src/normalizers/SaaqNormalizer.jl:85-114`)
Six near-identical `if !ismissing(...) push!(...)` blocks — 30 lines of boilerplate that could be a loop.

### 11. Inconsistent vcat Pattern
`SaaqNormalizer` uses `vcat(dfs..., cols=:union)`, `GrokOzempicNormalizer` uses `reduce(vcat, dfs; cols=:union)`.

### 12. Unused `import_root` Parameter (`scripts/build_saaq_dashboard.jl:25`)
`compute_heatmap_data` takes `import_root` and `bucket_count` kwargs that are never referenced.

### 13. `using JSON: parse` Shadows `Base.parse` (`src/Surrogate_Viz.jl:7`)
Prefer `using JSON` and `JSON.parse(...)` explicitly.

### 14. Redundant `ismissing(v) || v === missing` (`scripts/build_saaq_dashboard.jl:72`)
`ismissing(v)` already covers `v === missing`.

## Low Severity

### 15. Redundant `using Statistics` (`src/kernels.jl:1`)
Parent module already imports it.

### 16. `getfield` Re-exports (`src/Surrogate_Viz.jl:335-344`)
Opaque and fragile pattern for re-exporting normalizer functions.

### 17. Dict Built in Two Steps (`src/Surrogate_Viz.jl:94-108`)
Should include all keys in the initial constructor.

### 18. Double Computation of Deltas (`src/Surrogate_Viz.jl:120+122`)
`joined.delta_on_minus_off` is computed, then `compute_pairwise_deltas` recomputes the same values.

### 19. Inconsistent Fallback for `raw_summary["metrics"]` (`src/Surrogate_Viz.jl:285 vs 290`)
Two different fallback values for the same key.

### 20. No Docstrings in `GrokOzempicNormalizer.jl`
`SaaqNormalizer` has proper docstrings; `GrokOzempicNormalizer` has none.

### 21. Unused `dirs` Variable from `walkdir`
Both normalizers bind `dirs` but never use it. Use `_` instead.

### 22. Hardcoded Empty DataFrame Column Schemas
Both normalizers have fallback empty DataFrames with hardcoded column names in multiple places.
